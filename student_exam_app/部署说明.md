# 考试系统部署说明

## 本机跑起来

```
cd student_exam_app
pip install -r requirements.txt
python app.py
```

默认 5000 端口，浏览器打开 http://127.0.0.1:5000 。题目从 `materials/<科目>/<题号>/3题干.docx` 读，素材从同目录下载。

## 上线（Linux + 宝塔）

第一次先把 `deploy.json` 填对：

| 字段 | 说明 |
|------|------|
| host | 形如 `root@1.2.3.4` |
| ssh_port / ssh_key | SSH 端口和私钥路径 |
| remote_dir | 项目在服务器上的绝对路径，比如 `/www/wwwroot/exam`；留空则按 `remote_hint` 自动搜 |
| app_port | 服务实际监听端口，探活用 |
| install_deps | 依赖有变化时设 true |
| pip_cmd | 服务器上装依赖的命令，宝塔要写成对应虚拟环境的 pip |
| reload_cmd | 重启方式，默认 `touch wsgi.py`（uwsgi --touch-reload） |

然后：

```
python deploy.py --dry-run     # 只预检和打包，不碰服务器
python deploy.py               # 真部署
```

流程是本地跑一遍回归测试 → 打包 → scp 到 /tmp → 服务器先备份到 `../exam_backups`（保留最近 5 份）→ 解包 → 重启 → 请求 `/api/health` 探活。

预检不过会直接中止，不会传到线上。


## 服务器端要求

- Python 3.8+（线上是 3.14）
- `pip install flask`
- 目录可写（`uploads/` 放临时上传，判分完自动清理）
- 注意：uwsgi 的 `sys.executable` 是 uwsgi 本身，`app.py` 会取同目录的 `python` 来跑评分器，也可以用 `EXAM_PYTHON` 指定

| EXAM_MAX_UPLOAD_MB | 50 | 单文件上限 |

## 安全加固（2026-10-30）

服务器上这套服务和小程序后端（wx.xiaoshizi.asia、8001 Go 服务）同机，改动只碰
`student_exam_app` 自己的 vhost 与 uwsgi，别的主站配置不要动。

已做：

- uwsgi 只听 127.0.0.1:5000（原 0.0.0.0），外部只能经 nginx；加 `harakiri=90`、
  `max-requests=1000`、`limit-post=50MB`。改完用完整路径重启：
  `/www/server/pyporject_evn/xiaoshizi/bin/uwsgi --stop uwsgi.pid; uwsgi --ini uwsgi.ini`
- nginx vhost：`X-Content-Type-Options`/`X-Frame-Options`/`Referrer-Policy` 三个响应头，
  `location ^~ /uploads/` 直接 404，`/api/grade/` 单独限流
  （`limit_req_zone $binary_remote_addr zone=exam_api rate=120r/m burst=20`），
  TLS 只留 1.2/1.3。加固脚本 `tools/server_harden.py`，跑前会自动备份。

应用层：

- `/api/grade` 单 IP 每分钟 60 次（`EXAM_RATE_PER_MIN` 可调），按学校机房共用出口 IP
  的规模定，脚本狂刷仍会被 429。
- 500 错误只回"服务器开小差了"，堆栈只进日志；`/api/health` 不再暴露解释器名。
- 下载接口按前缀过滤，`1结果.*` 永远不会被发出去（实测返回的是 2素材.zip）。

仍需在控制台/面板处理（脚本改不了）：

1. 宝塔面板 23000 对公网开放且没设安全入口 —— 面板里开启"安全入口 + 面板 SSL +
   二次验证"，阿里云安全组把 23000 限制为常用 IP。
2. MySQL 3306 监听 0.0.0.0（目前被安全组挡住、无外部连接）—— 建议改
   `bind-address=127.0.0.1`，重启 mysql 会中断小程序几秒，挑低峰做。
3. fail2ban 已启用；如需再防扫描，可在面板"系统防火墙"里把 31318 限制来源 IP。

## 机房并发与限流（2026-10-30 调优）

一个机房几十台机器共用出口 IP，按"每 IP 每分钟几次"限流必然误杀。现在的设定：

| 项目 | 值 | 说明 |
| --- | --- | --- |
| uwsgi | `processes=2 threads=4` | 两进程，合计 8 线程 |
| 每进程判分并发 | `EXAM_MAX_PARALLEL=2` | 合计同时 4 份在判 |
| 排队等待 | `EXAM_QUEUE_WAIT=15` | 排不到才返回 429，不是立刻拒绝 |
| 单 IP 频率 | `EXAM_RATE_PER_MIN=600` | 40 人各判 3 次也够 |
| nginx 网关 | `exam_api 1200r/m burst=200` | 只挡脚本狂刷，不挡正常突发 |
| fail2ban | 只有 ftpd、sshd 两个 jail | **不会因为 429/404 封 IP** |

实测（同一出口 IP 并发提交）：

| 并发 | 结果 | 耗时 |
| --- | --- | --- |
| 20 | 20/20 成功 | 4.1 秒 |
| 40 | 40/40 成功 | 7.3 秒 |
| 80 | 80/80 成功 | 12.7 秒 |

压测脚本 `tools/loadtest_grade.py N`，改完并发参数建议跑一遍 40 和 80。

已知现象：80 并发瞬间首页可能要等 5-9 秒（uwsgi 线程都在排队等判分）。
正常上课提交是分散的，不会持续撞这个峰值；如果要彻底消掉，可以把首页渲染成
静态文件交给 nginx 直接返回，只有 `/api/*` 走 uwsgi。
